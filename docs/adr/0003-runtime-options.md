# ADR-0003 把运行时参数交给调用方，但不是全部

- **状态**：已采纳
- **日期**：2026-09-20

## 背景

流程中有 23 个硬编码的时间常量，取值来自本机实测。
但实际运行环境差异很大：视频从几十兆到几个 G，网络从千兆到共享带宽，
机器从开发机到低配云主机。同一套固定取值不可能在所有环境下都合适。

调用方还提出了另外三类需求：在特殊网络下追加浏览器启动参数、
批量调度时压低日志量、以及发布纯内容视频时跳过挂车。

## 问题

「把配置交给调用方」听起来只有好处，实则有个陷阱：**暴露得越多，越难用对**。

23 个时间常量里，只有一部分是调用方有判断依据去调的。
比如「等待视频上传完成」，调用方知道自己的视频多大、网络多快，能算出合理值；
而「点击选项后停顿 0.5 秒等页面渲染」，调用方凭什么判断该填多少？
把它暴露出去，得到的不是灵活性，而是一个没人知道怎么填的字段——
填错了还会造成时序相关的间歇性失败，这类问题极难排查。

浏览器参数与跳过步骤则有各自的风险：前者可以传入破坏程序前提的参数，
后者可以把流程掏空到失去意义。

## 决策

### 一、按「调用方是否有判断依据」划分超时

只暴露 8 个，每个都能说清「什么情况下该调」：

| 字段 | 默认 | 什么时候该调 |
| --- | ---: | --- |
| `total` | 600 | 调度方要控制单任务占用的时间片 |
| `navigate` | 60 | 网络慢，打开创作者中心本身就很久 |
| `pageReady` | 30 | 机器性能差，页面渲染慢 |
| `element` | 15 | 页面整体卡顿，元素出现普遍偏慢 |
| `cartModal` | 15 | 商品信息查询慢 |
| `upload` | 300 | **最常调**：视频大、上行带宽窄 |
| `coverFrame` | 60 | 长视频抽取封面候选帧耗时长 |
| `publish` | 120 | 平台侧审核前置校验慢 |

其余 15 个（各类渲染停顿、轮询间隔、内部匹配策略、清理超时）保持内部常量。
它们是实现细节，不构成对外契约——将来改实现时不必考虑兼容。

`element` 的默认值取 15 而非 10 有个具体原因：此前不同步骤分别用 10 与 15
（编辑器与发布按钮用 15，其余用 10），统一成一个字段时必须选一个。
取较大者，是因为往小了统一会缩短等待上限、可能引入新的偶发失败；
往大了统一只影响失败路径的耗时，成功路径完全不受影响。

### 二、浏览器启动参数：追加，但拒绝会破坏前提的参数

调用方给的参数**追加**在内置参数之后，不替换。同时拒绝三类：

| 拒绝的参数 | 原因 |
| --- | --- |
| `--user-data-dir` | 画像目录由 `userDataDir` 字段指定。从这里改会让「启动前清场」清理错目录，导致浏览器因目录被占用而启动失败，且失败原因看起来毫不相干。 |
| `--remote-debugging-port` / `--remote-debugging-pipe` | Playwright 靠它与浏览器通信，被覆盖会直接失去控制。 |
| 不以 `--` 开头的项 | 大概率是拼装错误。静默忽略只会让人对着一个不生效的配置反复调试。 |

**拒绝而不是静默忽略**：配置没生效却不报错，是最难排查的一类问题。

### 三、跳过步骤：白名单，而非黑名单

可跳过：`title`、`setting`、`declaration`、`cart`、`cover`

不可跳过：`upload`、`await_upload`、`publish`、`await_publish`

理由：这四步构成「发布一个视频」的最小定义。允许跳过它们，
这个程序就不再是它声称的那个东西了——跳过 `upload` 发布的是空内容，
跳过 `publish` 则根本没有发布。

真正需要「跑完但不发布」的场景已经有专门的出口：
冒烟脚本的演练模式（见 [ADR-0002](./0002-fail-fast-on-cart-failure.md) 附近的
`DRY_RUN_STEPS`）。用白名单挡住这条路，避免生产配置被当成演练开关误用。

### 四、日志级别

`quiet`（仅警告及以上）/ `normal`（默认）/ `debug`（含元素查找细节）。
批量调度时用 `quiet` 可显著压低日志量。

## 结果

### 收益

- 不同环境可各自调优，无需改代码重新打包。
- 暴露面小且每项都有明确的调整依据，配置不会退化成「一堆不敢动的数字」。
- 内部常量仍可自由重构，不构成兼容负担。

### 代价

- 配置模型变复杂，需要相应的校验与文档。
- 两处白/黑名单需要随流程演进维护——已用测试锁定。

### 兼容性

全部字段可选，缺省时行为与此前完全一致，上游无需改动。
